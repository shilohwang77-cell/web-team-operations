2/7

以「主責任」重新定義協作：行內設計師主責平台設計體驗、與開發團隊溝通，廠商設計師主責承接功能專案。

  • 掌握平台整體設計方向
  • 負責重要設計議題與跨團隊協調
  • 管理 Design Library 與設計一致性

廠商設計師｜專案 Owner

  • 獨立負責完整專案與 UX / UI 設計
  • 參與需求分析、設計交付與 Design QA
  • 與 PM、PO、RD 協作並對成果負責

UED Web Team｜04

Library 關係圖

4/7
  1. 網銀 Library 是核心元件。線上申辦 Library 與網銀 Library 相當接近，僅尺寸、間距、色票、icon 有些微差異。
  2. 網銀 Library 加上 AI Code Connect 後，為私銀 AI Library。
線上申辦 與網銀 Lib 相當接近 僅元件尺寸、間距、色票、icon 有些微差異
相當接近
網銀 核心元件 作為跨產品共用元件基礎
= 外觀樣式相同
加上 AI Code Connect
網銀 AI = 私銀 AI 網銀 Lib + AI Code Connect 與網銀 Lib 長相一致
拉齊優點
Library 彼此差異不大，若能拉齊讓 網銀、私銀、線上申辦只需共同維護一套設計元件庫，未來設計師調度支援也會更加順暢。

UED Web Team｜05

網銀/私銀/線上申辦 Library 發展方向

5/7

網銀 Library 與網銀 AI Library 長相一致，AI 版本多了 AI Code Connect；網銀 AI Library 也就是私銀 AI Library。線上申辦以此為基礎逐步完成元件合併。

盤點線上申辦 Library 元件 依照與網銀 AI Library 的差異程度分流
→
情況一｜相似 調整線上申辦 Storybook 共用元件 網銀 AI Library 不需變動，可沿用或微調共用規格
情況二｜差異較大 新增元件到網銀 AI Library 既有元件無法使用，也無法微調共用時，補齊新元件規格
→
兩部分皆完成 = 完成合併 線上申辦與網銀 AI Library 合併，形成跨產品共用 Design Library 基礎

UED Web Team｜06

新人的定位與階段發展

6/7

從線上申辦專案與元件整合開始，逐步承接線上申辦平台責任與網銀專案，長期發展 Web 跨產品能力。

Phase 1｜短期

線上申辦專案＋線上申辦與網銀 AI Library 整合

承接線上申辦專案，盤點可共用微調與需新增元件，建立跨產品 Design Library 思維。

Phase 2｜中期

線上申辦平台設計 Owner ＋ 網銀專案

主責線上申辦平台設計方向與品質，並於 2027 Q1 增加網銀完整專案責任。

Phase 3｜長期

Web 跨產品能力（網銀平台設計 Owner？）

累積 Web 跨產品設計與協調能力，並評估網銀平台設計 Owner 的發展方向。

7/7
