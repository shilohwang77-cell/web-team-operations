UED Web Team｜02

設計團隊分工與發展規劃

2/6

以「主責任」重新定義協作：廠商設計師主責承接功能專案，正職設計師主責產品/平台設計方向、跨團隊協調與設計決策。

廠商設計師｜專案 Owner

  • 獨立負責完整專案與 UX / UI 設計
  • 參與需求分析、設計交付與 Design QA
  • 與 PM、PO、RD 協作並對成果負責

正職設計師｜產品／平台 Owner

  • 掌握產品／平台整體設計方向
  • 負責重要設計議題與跨團隊協調
  • 管理 Design Library 與設計一致性
兩個角色皆有設計執行的任務，但角色差異在於組織責任、決策權與協調範圍，而不是設計能力或工作量高低。

UED Web Team｜03

長期團隊發展方向

3/6

每個產品都有明確 Designer Owner，讓角色責任清楚、專案經驗完整，並避免能力集中與工作負荷失衡。

角色定位 主要職責 長期方向
正職｜產品／平台設計 Owner
掌握產品／平台整體設計方向 決策重要設計議題 跨團隊、跨產品協調
承擔更高層級的設計決策與組織責任
廠商｜專案設計 Owner
需求分析與問題釐清 UX / UI 設計與交付 Design QA 並對成果負責
獨立承擔完整專案
所有 Designer｜共同成長
累積完整專案經驗 共同貢獻 Design Library 與方法
持續成長，維持相近的設計能力與工作負荷
最終目標 避免廠商長期只接零碎需求造成能力斷層與工作負荷失衡；正職承擔設計決策與組織責任，廠商獨立承擔完整專案，讓所有 Designer 持續成長並維持相近的設計能力與工作負荷。

UED Web Team｜04

Library 發展方向

4/6

主要以網銀平台與線上申辦平台為核心，不讓各平台各自長成孤島，而是逐步形成跨產品共享的 Design Library。

核心基礎

以網銀平台現有 Library 作為 Components 的基礎，保留成熟規格與設計品質。

逐步對齊

線上申辦平台逐步對齊網銀元件，整理差異、調整規格與前端實作方式。

共同維護

由各產品 Designer 共同貢獻，避免 Design Library 依賴單一人員。

最終目標：以網銀平台與線上申辦平台為主，建立可跨產品共用的 Design Library。
Design Library Strategy

UED Web Team｜05

新人的定位與階段發展

5/6

從線上申辦專案與元件整合開始，逐步承接線上申辦平台責任與網銀專案，長期發展 Web 跨產品能力。

Phase 1｜短期

線上申辦專案＋線上申辦與網銀元件整合

承接線上申辦專案，盤點線上申辦與網銀 Library 差異，建立跨產品 Design Library 思維。

Phase 2｜中期

線上申辦平台設計 Owner ＋ 網銀專案

主責線上申辦平台設計方向與品質，並於 2027 Q1 增加網銀完整專案責任。

Phase 3｜長期

Web 跨產品能力（網銀平台設計 Owner？）

累積 Web 跨產品設計與協調能力，並評估網銀平台設計 Owner 的發展方向。

Designer Growth Path
